## Contracts

`lab/pilot02_runtime.py` supplies `Pilot02MacBridgeAdapter`. It loads the sealed V0 transport source into an isolated Python module and binds its context validator before use. This preserves the public `task_policy` without patching the shared V0 validator, copying HTTP code, or changing any original source. The inherited transport retains the original authentication, total deadline watchdog, one cancel request, usage extraction and parameter checks. Offline fixtures use ephemeral localhost ports; production ports are forbidden in offline mode. The production bridge is imported only for pure payload/command validation; the fake server replaces its inference function before listening.

The adapter accepts only the 20 sealed jobs, exactly matching their context and three RGB SHA256 values. All 607 sealed artifacts and the seal itself are verified. The full remote CLI command must equal the original bridge command, including model, reasoning, ephemeral session, schema, images, provider and Code Mode switches. No prompt, model input, geometry, scorer or production bridge was changed.

Assessment independently reloads raw output, original bridge receipt, transport record, events, schema and hashes. It requires successful transport, return code 0, no error, exactly one `turn.completed`, a unique `thread.started`, usage and strict JSON. Scoring always calls `pilot02_contract.score()`, including positive local-z upright constraints for free yaw. Valid geometry failures remain `VALID` with score 0. Transport, timeout, incomplete, invalid JSON or parameter failures remain `NOT_SCORED` with null score. There is no answer repair. Each result has an independently reloaded and recomputed `independent_rescore.json`.

## Ledger and recovery

`lab/pilot02_dispatcher.py` owns a new ledger only. It never loads, edits or resets a Pilot 01 ledger. `prepare` refuses an existing directory. A host-wide exclusive lock, sealed order, fixed concurrency 1, 180-second client limit, unique thread IDs and no retries prevent accidental parallel/repeated dispatch. A reservation is atomically written and fsynced before transmission; interrupted attempts are never refunded. Source hashes bind the batch to this implementation. An offline fixture batch cannot be converted into a real batch.

`run` defaults to dry-run, including when a batch already has authorization. Real mode requires both `--real` and a fresh batch-bound authorization record. A grant is an operator record of actual human authorization, not proof generated by the software. Do not create or use one before new authorization. A grant cannot be replaced or expanded. There is no reset, retry, wave or worker option.

`status` and `reconcile` never access the network. Reconciliation can promote a reserved/unknown row only when its archived completion and independent scoring are confirmed. It advances to the next frozen sample, never reissues that row. Missing or inconclusive evidence leaves the batch stopped. Cancellation acknowledgement does not establish remote completion. Resolve an unknown remote job before seeking a separately authorized continuation. The exclusive lock is host-local: run the real batch on one designated host, never copy an active ledger to another host for concurrent execution.
