# Astra 六场景 A C 真实评测待授权方案

主目标恢复为测量 Astra 的任务导向空间规划能力，以及感知输入 A/C 的差异。B v1/v2、其诊断和反例保持原样，仅作为已有固定条件；停止 B v2 优化，不开发 B v3。本方案替代 B v2 报告中继续优化重建的工作方向，不改写历史报告或旧 36 次计划。

当前生成预算为 **0**。已准备六场景 × A/C × 两次独立调用，即 **24 次未来客户端派发**。此文件不是授权，不创建 ledger，也没有连接生产 bridge。

## 实际任务清单

| 场景 | 给模型的任务 | 主要判断 | 公共数据与独立评分 |
|---|---|---|---|
| v2_val_path_01 | 固定姿态搬运红色物体至公共目标区域，整件物体留在限定高度工作空间 | 障碍侧向避让及悬空横杆下方路径 | 三视角 RGB、标定；独立 GT 连续碰撞及边界检查 |
| v2_val_path_02 | 同类任务，障碍与通行侧改变 | 是否随当前场景调整路径 | 同上 |
| v2_val_path_03 | 固定姿态穿过含连接立柱及横杆的受限空间 | 区分横杆与立柱，满足整段路径约束 | 同上 |
| v2_val_yaw_01 | 在窄槽区域放置红色长方体，保持竖直，自选 yaw | 窄槽容纳和合法落点；初始 yaw 与该槽相容，不能单题据此证明主动旋转能力 | 三视角 RGB、标定；独立 GT 全体积容纳、碰撞、upright 检查 |
| v2_val_yaw_02 | 同类任务，不同槽方向及位置 | 自主朝向和放置决策 | 同上 |
| v2_val_yaw_03 | 同类任务，另一槽方向与空间余量 | 自主朝向和放置决策 | 同上 |

六场景均有明确公共任务、同步静态 RGB-D、相机标定、独立 GT、合法 witness 和非法负对照。所有场景保留，不因模型表现选取。GT 和 witness 仅用于评分/离线有效性检查，绝不作为输入附件。33 个原正负对照经原评分器验收。当前任务只衡量物体几何规划，不衡量机器人 IK、接触动力学、支撑稳定性或真机可执行性。

## 已准备的模型输入

`inputs/<scene>/RGB_MULTI_VIEW/` 为 A；`inputs/<scene>/RGB_ORACLE_3D/` 为 C。每份只有原 `context.json` 与三张 RGB，按字节复制既有 SAPIEN 输入；没有重新渲染或修改 prompt/schema。

A 包含原 RGB、标定、公共区域/工作空间、起点（路径任务）与任务约束。深度供离线研究归档，不发送给 A/C。C 在完全相同上下文中，仅多提供目标、障碍和区域的中心、尺寸、姿态等场景事实。C 的 geometry 与独立仿真场景事实精确一致，renderings 为空，不含正确目标姿态、参考动作、轨迹、witness 或评分答案。当前目标姿态是场景初态事实，不是放置答案。

`task_catalog.json` 包含实际任务、输入 SHA、评分器绑定和私有评分文件位置，属于实验管理资料，不能整体发送给模型。模型只收到对应 `inputs` 中的上下文和三张 RGB。原生产 bridge 的通用 payload 校验、schema 编译及公共上下文校验全部通过，均为本地函数调用，不启动 bridge 或模型。

## 固定顺序与运行规则

`future_ac_order.json` 已固定 24 项：第一轮按 path_01、path_02、path_03、yaw_01、yaw_02、yaw_03 顺序，条件先后为 AC、CA、AC、CA、AC、CA；第二轮场景顺序相同，条件先后全部反转。每次独立 ephemeral 会话，不复用输出作为后续上下文。每轮形成六个同题配对，总计 12 个重复配对、六个独立场景；两次重复不当作增加独立场景数。

固定 gpt-6-astra / medium，原 Mac ChatGPT → SSH bridge，单 worker 顺序执行，180 秒客户端截止，正式运行前核实 190 秒服务端超时。保持原 Code Mode 配置，不自动重试。合法 JSON 的几何错误计零分并继续；超时、传输错误、原生 CLI 错误/重连、完成状态未知、非法 JSON、参数漂移或完整性错误立即停止。每次派发消耗一次预算，上游生成次数与内部重连另列，不能声称客户端精确控制它们。

真实执行仍需新授权以及新批次生产预检。旧 Pilot02 入口绑定旧 20 项清单和预算，不可直接运行它的 next/wave，也不得使用任何旧 ledger。本轮只交付输入和顺序，不制造通用调度平台；正式执行前仅需将已有运行逻辑绑定到这份新清单及 24 次上限，完成离线验收后创建独立授权记录。

## 预先固定的报告口径

1. **空间事实估计错误：本方案标记 NOT_MEASURED。** 当前原 schema 只输出动作，没有独立事实估计字段，因此不能从 A 规划失败推出“模型看错了”。直接空间理解测试需要另行冻结事实提问，或明确批准修改本方案 schema；不能事后从 reasoning 文本挖数当作预注册结果。C 对提供坐标的复述不算空间推理提升。
2. **准确几何下的任务决策错误：** 对 C 的协议有效结果用原 `pilot02_contract.score()` 报告容纳、碰撞、整段路径、工作空间和姿态失败。属于准确几何可用条件下的决策/约束遵循错误，不推断模型内部原因。
3. **A/C 决策差异：** 按场景与重复编号配对，报告双成功、仅 A 成功、仅 C 成功、双失败；并保存原落点、姿态、路径及失败约束。比较路径与自由 yaw 两类，不根据 A 失败挑选样本。不同合法解同等接受，不用参考轨迹相似度评分。
4. **附加成本：** 原样记录输入 token、缓存 token、输出 token、reported reasoning tokens（未报告记缺失，不能填 0），客户端耗时与输入准备耗时。缓存命中配对另列；不把 token 当作精确内部计算量，不把客户端耗时当纯模型时间。

评分标准、2 mm clearance 和原 task_policy 均不改动。保留所有原始答案；基础设施/协议异常标记 NOT_SCORED，不能计为空间能力零分。独立重评分须一致。样本少，只做描述性和重复一致性分析，不声称总体能力提升或统计显著性。
