# 持物驱动/联动审查：返回值错误已修，D4 失稳仍未修复

基于 `a2a1474`，执行主机 ubuntu-robot。新增 Astra 请求 **0**；原 STOPPED ledger、剩余 11 次预算、历史原始输出与评分均未改。没有调整刚度、阻尼、限力、2 mm 保护、质量、摩擦、布局或模型动作。

确定修复了一个 Python 实现错误：`Arm.latch_grasp_contact()` 未回传父类的锁定记录，导致初始化夹紧循环没有记住“已锁定”，实际重锁了 90 次。最小修复仅保存并返回父类结果，修复后四项物理回归均只锁定 1 次。

**这没有解决 D4。** 原目标、原关节路径、原速度回归仍触发穿透；事先冻结的唯一交叉持物运动也失败。正常抓取、D3 移动、静止保持和开爪释放仍成立。没有选择更多控制器变体来追求 PASS。

实际运行版本：SAPIEN 3.0.0b1、PhysX `105.1-physx-5.3.1.patch0`、mplib 0.2.1；物理步长 0.004 s，原求解器迭代 10/1。版本、56 份资产及两批旧归档的独立核对保存在 `integrity_verification.json`。

`original_readback_01` 从原物理抓取和前三条提案恢复状态，逐步读取原生 joint getter；只读插桩不改控制。第 4 条前状态匹配原记录，仍于第 3844 步中止，穿透 2.597680 mm。

| 原主关节读回 | 数值 |
|---|---:|
| stiffness | 20 |
| damping | 2 |
| force limit | 0.10000000149 Nm |
| mode | force |
| position target | −0.447089344263 rad |
| velocity target | 0 |

这些属性从第 4 条开始到触发保护前只有 **1 组唯一值**，没有被运动代码覆盖。初始化/正常开爪时按原代码使用 URDF 的 10 Nm 上限，接触锁定后降至 0.1 Nm；本轮没有增加这些值。

保护触发时实际主关节为 −0.471134692430 rad，比固定目标更闭合 **0.024045348167 rad**，不能解释成“仍在追赶更闭合的目标”。保护后原 `hold()` 把目标设为实际关节值，这是停机动作，发生在故障之后；没有把它误当成故障前的覆盖。

从动关节原生读回为位置刚度 0、阻尼约 0.1、速度目标 0、原 URDF 限力 10 Nm。逐步记录同时保存了 `set_qf` 后、物理步前的额外广义外力命令；它不是测得的驱动力矩。原主关节该命令为正值约 0.00546–0.01985 Nm。驱动、tendon 的实际输出力矩/约束力均标记 **UNKNOWN**，没有用 PD 公式或冲量除以时间冒充原生测量。此命令/API 区分也与 [SAPIEN 官方说明](https://github.com/haosulab/SAPIEN/blob/master/docs/source/tutorial/robotics/basic_robot.rst)一致。

## 实际加载的联动关系

在原生 `create_fixed_tendon` 调用处只读记录成功接受的参数，左右各 5 条。由实际 link chain 与系数还原方程，再与加载 URDF 的 mimic 方程逐条比较：符号、比例、零偏匹配，5 条独立约束的矩阵秩为 5，对 6 个夹爪坐标留下 1 个理想闭合自由度。未发现重复、遗漏或不支持拓扑被静默跳过。

构建参数为 stiffness=100000、未显式提供 damping（该安装 API 默认 0）。安装版本没有可用的构建后 tendon 参数/约束力 getter；上述结论是成功构建调用及方程核对，不能冒称原生约束力读回。

每项误差严格使用实际声明的 `q_child − multiplier*q_parent − offset`：

| 从动关节 | parent / multiplier | D4 前误差 rad | 原 D4 中止误差 rad |
|---|---|---:|---:|
| Left_Support | Left_1 / −1 | 0.000274 | 0.010153 |
| Left_2 | Left_1 / +1 | −0.000165 | −0.001558 |
| Right_2 | Left_1 / −1 | −0.000053 | 0.003380 |
| Right_1 | Left_1 / −1 | 0.000059 | 0.002260 |
| Right_Support | Right_1 / +1 | 0.000272 | 0.004590 |

表中均省略共同的 `ctag_` 和 `_Joint`。Right_Support 的实际父关系是 Right_1，不能直接把它与 −Left_1 的差当作本条约束误差；其对 master 的总偏差还包含 Right_1 的上游误差。完整局部/逐项最大误差与原静止、两倍时长记录保留在 `archived_linkage_errors.json`。

### 区分整体闭合与机构偏离

使用现有 mplib 和实际 URDF/原网格做纯 FK，不写 PhysX qpos、不执行理想化姿态。实际 q 的 FK 开度与物理记录相差不到 0.000054 mm。把相同 master 下的从动坐标替换为理想 mimic 值，仅用于几何分解：

| 原 D4 开度变化的加性分解 | mm |
|---|---:|
| 记录的总开度变化 | −2.264448 |
| 理想单自由度、实际 master 进一步闭合的分量 | −2.889882 |
| 从动关系偏离对开度标量的分量 | +0.625463 |
| FK 与物理记录残差变化 | −0.000028 |

原接口“开度”是两夹垫代表点之间的距离，不是最小表面间距。这个分解表明整体闭合与联动偏离同时存在；偏离在该开度标量上反而抵消部分缩口，仍可能改变局部夹垫姿态。不能仅凭某项从动误差增大就认定它导致全部穿透，也不能据此把它视作安全改善。这是运动学分解，不是力学因果证明。

## 最小代码修复

`dual_scene.py` 的变化只有：

```python
result = super().latch_grasp_contact()
# 原有分支与控制参数保留
return result
```

父类 `gripper()` 用返回值保存 `latched`，原 wrapper 丢弃返回值使它始终为 None。原读回实际发生 **90 次**锁定（第 1526–1615 步），修复后为 1 次，后续目标不再被初始化循环反复重设。

它是本仓库的返回值错误，不是 PhysX 引擎 bug。原 D4 期间目标本就固定，因此没有把这个发现直接当成原运动失稳的根因。未实施额外限力、阻尼或 tendon 参数变体。

## 未解决的问题与证据边界

目前支持的事实是：D4 中 master 在固定目标下继续闭合，同时软联动误差扩大；驱动属性没有在运动中被覆盖，加载关系未发现符号/比例、重复/遗漏错误。仅靠 qpos、qvel、驱动设置和接触记录，仍不能可靠区分限力驱动的实际输出、tendon 约束作用及接触/求解器的相互作用。

缺少的关键证据是逐步原生驱动力矩、各 tendon 的约束力/冲量及对应求解状态。现有安装 API 没有提供可靠读回，已保持 UNKNOWN，没有把命令、估计力或时间先后当作引擎真值。故本轮只保留已证实的返回值修复，**不宣称持物运动已修好，不再增加场景或参数扫描，不调用模型**。
