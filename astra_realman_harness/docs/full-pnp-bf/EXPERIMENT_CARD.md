# 实验卡：共同完整任务上的 B 与 F

设计状态；当前 B/F 闭环均未实施。本卡定义第一条比较主线，不声称组件单项有效，也不把 stub 或历史 M/S 作为新结果。

## 1. 共同任务与冻结条件

起点：空夹爪、物体稳定在桌面。任务为根据当前 RGB 和合法机器人状态定位目标物与目标区域，完成接近、抓取、抬起/运输、放置、退出，再根据新观测判断结果。不能从 `setup_held()` 开始；抓取失败、抓空、遮挡、不确定、恢复、错误结束判断全部计入完整回合。

模型看到语义任务（如“将桌面红块放入绿色目标区并退开”）、同一动作语义、相机/机器人标定和共同公开几何先验。不会收到物体/目标区的模拟坐标、`sim_rm65_targets.json` 的正确释放点、专家路径或动作列表答案。机器人标定、桌面平面、任务公开尺寸属于声明过的共同先验；物体/目标位姿必须由当时图像推断，有误差/unknown，不能用先验中的固定坐标绕过视觉。

共同接口选定为既有 RM65 **有界 Cartesian action chunk**：每次1–3个 `move_pose([x,y,z,qw,qx,qy,qz])`、`gripper(opening)` 或 `hold(seconds)`；另有 `observe`、`finish`、`stop`。位置是世界坐标下动态指垫中心，朝向是 Link6 wxyz；不是关节、力矩或真机RPY接口。两条件固定此接口、同样的可选动作与恢复能力，不以 continue/stop 审批写死的完整任务。具体合法边界见协议。

两组复用冻结的 SAPIEN/PhysX、RM65、mplib/OMPL/FCL/TOPPRA、原碰撞/关节/跟踪监控、速度、接触预载、三路 `assembly/fixed/wrist` 相机布局与640×480 RGB、视频设置。同一单owner执行权，模型仅提案。相机采集能力完全相同，附件选择属于实验组件；没有F专属相机、精确检测器或机器人动作。

## 2. 两个闭环

| 项目 | B：合理同步基线 | F：四部分最小组合 |
|---|---|---|
| 动作与观测能力 | 同一chunk、观察/主动调整腕视角、保持/结束接口 | 完全相同 |
| 模型职责 | 单一行动决策者，一次调用完成当前观测判断和下一chunk提案 | E证据/视图子代理 → A行动子代理；独立请求、独立输入输出schema与日志，非单prompt扮演 |
| 请求时机 | 当前chunk结束后，按新观测同步推理；等待保持 | 获得合法新快照后，可在已批准chunk执行期间启动下一轮；最多一个未来候选 |
| 常规附件 | 三路当前全图；有历史时可附最近一次动作前的fixed图（第四槽），附真实时间戳 | E看三路当前缩略图与可选旧关键帧；A至少一张当前全局图，再按E输出选择细节视图/ROI/旧关键帧，最多四张 |
| 额外观察 | 可提出重观测/指定现有相机或合法ROI需求；算新耗时/调用 | 相同能力；E/A的额外需求全部计费，不能把E采集视为免费 |
| 默认历史 | 最近5条已完成、字段完整的实测transition + 当前未解决执行错误；同样保留unknown | 有界事件/证据记忆：近况、仍未解决的失败、最后可见物体/目标证据与关键帧；来源、年龄、失效条件均保留 |
| 调度与执行权 | owner校验后执行 | E/A只能给证据或提案；同一owner提交，不能相互授权执行 |
| 失败与恢复 | 新观测后可重规划；真实执行错误/协议故障按共同停止规则 | 同样恢复边界，旧未来候选先失效；不得用更多未计费请求挽救F |

B允许同一请求输出合理的多动作chunk、使用标定与历史、主动重看和纠正，不限制为逐原语一次调用，也不故意去掉必要反馈。所有动作预算/权限对称。F可能消耗更多图片、调用与等待；不预设选择图像就更便宜。

E/A都计划沿用同一 `gpt-6-astra / medium` 通道，客户端工具关闭；不开放模型内置spawn、shell或场景读取。角色分工由宿主的明确任务队列和受限worker实现。首版**全局最多1个模型请求在途**，因此“多角色”不等于“模型并发”。它们可顺序运行并与owner执行重叠。若独立消息/依赖证据不存在，不能把运行标为F。

## 3. 四部分的实际职责

| 部分 | 输入 | 输出与依赖 | 何时更新/失效 |
|---|---|---|---|
| 异步调度 | 已批准chunk、真实进度、冻结快照、预算、候选slot | 调度E/A；维护一个未来候选；不计算物体真值 | 父执行失败、STOP、任务/标定版本变化即取消；按真实接续门提交 |
| 视角/局部选择 | E当前三图缩略图、原图尺寸/相机标定、合法历史；不能先看后续图 | 带原图hash的camera排序、像素bbox或unknown、可见性claims；owner只裁其指定的既有图 | 新相机姿态/遮挡/低置信/跟踪失败后旧ROI失效；回退全图或新观察 |
| 历史维护 | owner完成事件、实发/实测差异、带来源的图像证据、取消/错误 | 类型化记忆和有界投影，原日志不删；模型判断另存hypothesis | 仅完成事件入实测历史；新证据可撤销旧假设；提案/预测不能冒充结果 |
| subagent分工 | E收到证据任务；A收到同源观测、所选图片、E产物hash与合法历史 | E返回证据包、不能动作；A返回动作候选/观察需求/结束判断；owner唯一提交 | 独立role_id/request_id/parent_hash、raw/parsed；禁止角色互相背书当真值 |

E在初始、抓取后、释放后及视图/对象假设失效时调用；其它连续运动段可复用仍有效的E产物，附原年龄，不为展示分工强制每步调用两次。需要E时必须先完成E再发A，不能在A发出后偷偷把后来的证据塞回输入。若某短回合未实际触发四组件，照实记录组件暴露量；不人为补请求凑“完整F”。

## 4. 可见性覆盖与配对

首批开发材料覆盖两类：N，常规视角中任务对象/目标可辨；O，抓取/运输/释放时机器人、夹爪或所持物造成的真实遮挡。相机安装不变，不用遮罩替换图像制造F优势。使用公开任务类别相同、不同初始物体/目标位置的可达场景；只在初始化放置，禁止回合中瞬移。

在开发阶段用实际当时RGB确认存在操作遮挡的示例，冻结场景生成配置后才评估；不靠GT mask/未来帧给模型选择视图、ROI或phase。初始场景分层预先确定；实际遮挡随策略动作而变，另由盲评当前帧/视频标注为诊断指标，不按事后“F恰好遮挡少”删样本或重新配对。遮挡没实际发生也保留并标NOT_EXPOSED。

先B、F在同一批初始化参数上配对，运行顺序交替B/F与F/B；每次新进程、独立物理重置并记录起点，不称精确状态克隆。开发和评估按来源回合/场景配置分开，同一回合的帧不当独立样本。seed仅是生成/规划随机数记录，不自动等于布局。

## 5. 成功定义与成本

独立评分覆盖全链：从桌面抓取并稳定抬起、运输中未失落、物体最终稳定在目标区、夹爪释放并退出、模型在有效当前证据下正确结束。继承旧全任务评分的≥50mm抬升连续300步、目标区/稳定/滑落指标；新增明确退出判据（待离线锁定：夹爪打开、指垫中心至少桌面80mm高，指垫与物体无接触且几何最短距离≥30mm）。这是评分/防碰撞阈值，绝不作为模型正确目标坐标。

物理任务分数与模型结果判断分开：physical_success、model_verdict(done/not_done/unknown)、有证据结束与否、false_done、漏判。模型说done不等于成功；物理成功但不知道/没有退出或没有完成判断，不算严格全闭环成功。过早stop、unknown、预算耗尽、失败均保留，另报物理已达成部分。接触安全/GT不能向模型发“任务已完成”。

完整墙钟从空夹爪起点首观测之前开始，含所有感知、推理、角色协调、抓取/运输/放置/退出、重看/恢复、结束判断和独立稳定评分。初始化/通道预检单列；任何物体相关动作不能藏在初始化。报告所有回合的成功/失败/unknown、预算惩罚完成时间、成功回合耗时（次要）、独立评分、停止原因及全部成本。先报告B/F组合差值及区间，不分摊为四个组件各自贡献。

## 6. 组合后再替换

先获得B/F完整结果，包含正常、遮挡、失败及成本记录；**无需四组件分别胜过B才允许F运行**。之后按证据做单项替换：F改同步、F改固定全图、F改B的近5条历史、F改集中式角色。保持共享接口/保护不变，一次替换一项，明确是在完整组合中的条件贡献，不是普适主效应。

仅追查有依据的关键交互，例如异步×视图新鲜度、记忆×遮挡、分工×额外调用。届时另设计小型对照和预算；不立即跑16组、不把单项提升相加、不预设四组件永久保留。若F不如B，应允许缩减/替换组合；不能隐藏失败或只报最有利片段。
