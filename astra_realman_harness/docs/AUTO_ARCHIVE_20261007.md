# 每轮自动归档

从本补充版本开始，GUI 和原终端入口都会在回合结束、summary 写入后自动保存整轮。
包括 H1D0/H5D0/H1D1/H5D1、原三视角、原五步历史、原四视角，以及 GUI 合成演示。
无需增加启动参数，终端输入的 task 与 `--task` 参数采用同一规则。

保存目录（相对于正在运行的 harness）：

```text
logs/episodes/将夹爪中的球放入框内__20261007_143025_123456_CST/
  task.txt                 原任务完整原文（含空格/换行/中文）
  index.html               双击打开，逐步看图片、公开诊断、动作、执行反馈
  episode.json             整轮结构化索引和全部步骤
  images/                  本轮观测及模型输入所引用的 PNG 原始字节
  record/step-01/...       模型上下文、原始回答、诊断、解析动作、实发与回读
  record/step-02/...
  record/summary.json      本轮结束状态
  record/...               原配置、来源、版本等记录
  console.log              GUI 原始终端输出（关联文件存在时）
  manifest.json            文件 SHA256、大小及缺图/校验提示
```

文件夹名为任务指令 + **Asia/Shanghai 北京时间**，时间取自动归档时刻，精确到微秒。
非法文件名字符和换行替换为 `_`，过长任务名按 UTF-8 字节数截短；完整任务仍保存于 task.txt 和 episode.json。
同任务连续运行不会覆盖。多次触发同一回合的归档复用已有结果。
图像按内容去重，逐步附件列表仍保留每一路、每一次使用的顺序、角色、序列号和时间。图片不会重新压缩。

每轮完成后终端输出 `AUTO ARCHIVE →` 和保存路径；GUI 底部显示“整轮已自动保存”，并提供“下载整轮归档”按钮。
原始 logs 目录不移动、不重命名，已有回放/报告仍使用原路径。
成功、达到步数/时间预算、IK/模型失败、正常人工停止的已结束回合均尝试保存。归档在执行器退出后进行，不改变决策、动作或重试策略。
如果没有公开诊断（例如 D0），明确记录“没有公开诊断”，不会补写模型内部推理。

归档采用临时目录 + 完成后重命名。磁盘写入失败会报告 FAILED，保留原始日志；缺图、哈希不符或无法解析的记录会在 manifest 中提示。
强制杀进程、断电或磁盘故障不能保证完成归档；原逐步日志仍是恢复依据。
自动归档是**结束时快照**，回合结束后新加的人工标注仍保留在原日志中，可通过原证据导出功能另行导出。
只对升级后的新回合生效，不会自动重命名或批量改动之前的实验记录。

## 使用

启动命令保持不变，例如：

```bash
bash launch/H5D1.sh --mode execute --max-steps 10 \
  --task '将夹爪中的球放入框内，完成后让夹爪离开框。'
# 一轮结束后直接看 AUTO ARCHIVE 输出，无需再手动保存。
```
