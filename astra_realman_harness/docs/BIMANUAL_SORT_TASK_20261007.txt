====================
最终 V1 demo
====================

桌面混放若干物体：

fruit:
- apple
- banana
- orange

clutter:
- tennis ball
- packet / block 等明显非水果物体

空间设计：
- source zone：物体位于左臂可达、右臂不可直接操作区域
- handoff zone：左右臂共同可达的固定交接区域
- destination zone：右臂侧
    fruit -> plate
    clutter -> box

完整任务：

1. Astra 观察全局并选择一个未处理 object
2. 判断该 object 属于 fruit / clutter
3. 左臂拾取
4. 左臂把 object 提交到 handoff region
5. 右臂接取
6. 只有确认右臂已经可靠持有后，左臂才释放
7. 左臂退出 handoff region
8. 右臂将：
      fruit -> plate
      clutter -> box
9. 验证结果并更新共享状态
10. 处理下一个 object

第一版采用：
ONE Astra + shared task state + two arm executors
不是两个独立 Astra。

====================
核心设计原则
====================

Astra 提升到高层，不再默认每几厘米调用一次。

高层动作优先设计成：

OBSERVE
SELECT_OBJECT
LEFT_PICK(object_id)
LEFT_PRESENT(object_id, handoff_region)
BIMANUAL_HANDOFF(object_id)
RIGHT_PLACE(object_id, destination)
VERIFY(object_id)
RECOVER(...)

保留底层 delta action 能力作为：
- 精细修正
- 失败恢复
- 调试接口

但正常 demo 不应要求 Astra 每 3~4 cm 重新决策。

模型 effort 第一阶段固定 medium。

不要做“把 Astra 输出统一乘 N 倍”的 hack。
不要用 minimum step 强迫所有动作变大。

====================
共享 task / belief state
====================

建立明确的共享状态对象，例如：

objects:
  fruit_01:
    semantic_class: fruit
    subtype: apple
    holder: none | left | right
    stage:
      unprocessed
      left_grasped
      handoff_ready
      right_grasped
      sorting
      placed
      failed
    destination: plate
    confidence / evidence

task_state:
  active_object
  phase
  left_arm_state
  right_arm_state
  handoff_state
  completed_objects
  failed_objects

所有状态变化必须有 observation / execution evidence。
不能因为 SDK return=0 就自动声明 grasp/handoff/place 成功。

旧 belief 可被新视觉证据推翻。

====================
handoff 必须显式建模
====================

handoff 第一版采用顺序 handshake：

LEFT_HOLDING
-> LEFT_AT_HANDOFF
-> RIGHT_APPROACH
-> RIGHT_GRIP
-> RIGHT_HOLDING_CONFIRMED
-> LEFT_RELEASE
-> LEFT_RETRACT
-> RIGHT_OWNS_OBJECT

核心 invariant：

RIGHT_HOLDING_CONFIRMED 之前，
LEFT_RELEASE 禁止执行。

不要第一版就做双方任意同步运动。
除了 handoff 所需的受控动作外，默认一侧运动时另一侧 hold。

handoff 失败必须进入 RECOVER，
不能让两边各自继续执行。

====================
视觉 / history
====================

不要把无限 RGB 历史全部塞给模型。

准备 keyframe memory：

1. current views
2. previous action before/after
3. last_clear_object_view
4. last_clear_destination_view
5. pre_handoff view
6. post_handoff view

history 中保留：

- proposed high-level skill
- actual execution result
- measured arm motion
- gripper feedback
- object holder transition
- important visual evidence

目标：
让模型知道“上一动作改变了什么”，
而不是只知道“上一动作发了什么命令”。

关键帧必须带：
- camera id
- timestamp
- observation id
- reason_selected
- object id

不要把旧图当成当前状态。
